## 0.3 布局函数（纯函数，一次成型，无求解器、无失败分支）

```
输入：P_S, P_E, P_M（投影点，CSS px）
阶段 1（地月分离，方向锁定在 ±e）
  r = P_M − P_E ; d = |r|
  t = min( max((SEP_X − d)/2, 0),  MAX_OFF · min(1, d/d₀) )
  d < EPS 时短路 t = 0（不计算 e）
  C_E = P_E − t·e ; C_M = P_M + t·e
阶段 2（太阳让位，方向锁定在 +u_s）
  M0 = (P_E+P_M)/2 ; u_s = (P_S − M0)/|P_S − M0|   （|·| ≥ 14.2，恒非零）
  对 X ∈ {E,M}：x_X = (P_S − C_X)·u_s ；w_X = |(P_S − C_X) − x_X·u_s|
  s_X = clamp( sqrt(max(R_YIELD² − w_X², 0)) − x_X , 0, MAX_OFF_S )
  s   = max(s_E, s_M)
  C_S = P_S + s·u_s
```

**阶段 2 单向依赖阶段 1，无反馈、无迭代、无不动点求解 ⇒「无解」状态在结构上不可能存在 ⇒`__unsolvable` / `el.remove()` 代码路径被根除。**

# 1. 裁决论证

## 1.1 先复核简报数据（结论：全部自洽，可直接采信）

我用独立的几何模型反推简报的实测数，得到一个**恒等式**：

> 当 `t = (SEP_X − d)/2` 未被 clamp 时，两中心对称分布于地月投影中点 `M0` 两侧，**`|C − M0| ≡ SEP_X/2 = 12.2` 恒成立（与 d 无关）**。
> 故 `最坏 |C − S| = anchor_min − 12.2`。

逐视口验算：

| 视口 | anchor_min − 12.2 | 简报「最坏 \|C−S\|」 | 偏差 |
|---|---|---|---|
| 1400×913 | 58.48 − 12.2 = 46.28 | 46.283 | 0.003 |
| 1280×900 | 53.47 − 12.2 = 41.27 | 41.275 | 0.005 |
| 480×850 | 22.56 − 12.2 = 10.36 | 10.381 | 0.02 |
| 390×844 | 18.33 − 12.2 = 6.13 | 6.131 | 0.001 |

四个视口全部吻合到小数点后 2–3 位（残差来自 anchor_min 的舍入显示）。再验第二组：`center 失败 2252 / (2 标签 × 200,177 帧) = 0.563% ⇒ 通过率 99.437%`，简报给 99.435%；`19217 / 200,177 = 9.60%`，恰等于简报的「`|C−S| ≤ 12` 占比 9.6%」——**因为任意两点相距 24.4 > 24，不可能同时落进半径 12 的太阳圆**（引理 L1），所以每个"占比帧"恰好贡献 1 次失败。

**结论：简报数据无误，且我的几何模型与它逐位一致。**后文所有推导可直接套用这套包络。附带得到引理 L1（至多一个地月中心可被太阳遮挡），它保证 `max(s_E, s_M)` 在绝大多数帧只有一项非零。

## 1.2 三个前提为何全部否决

### 前提 A（缩小地月）——**既无效又昂贵，双重否决**

1. **无效**：简报自己的表已经给出结论——缩到 16 px 仍不能脱离太阳圆。原因在恒等式里：`|C − M0| = gap/2`，而 `gap` 下界由 geometry 门禁锁死在 24.0，所以 `|C − M0| ≥ 12.0` 与按钮半径**无关**，最坏 `|C−S| ≥ 18.33 − 12.0 = 6.33`，永远小于任何 ≥ 6.33 的太阳半径。缩小 `R_EM` 只把太阳圆的边界往里挪，两者同步缩小，净空不变。
2. **昂贵**：24 px 是 WCAG 2.2 AA SC 2.5.8 的**绝对下限**，不是建议值。其唯一豁免（Spacing Exception）要求"以每个欠尺寸目标包围盒为心的 24 px 直径圆互不相交、且不与其他目标相交"——而移动端 `anchor ≈ 18 < 24`，太阳与地月的 24 px 圆必然相交，**豁免条款在本场景不可满足**。即缩小不仅不解决问题，还把一个可论证的合规状态换成一个不可论证的状态。

### 前提 B（z-order 调换）——**与零容忍门禁正面冲突，无可挽救**

太阳 target 判据是 `elementFromPoint(P_S) === 太阳按钮`。一旦地月 z 高于太阳，只要 `|C_E − P_S| ≤ 12` 就必然夺走探针；而 `|C_E − P_S|` 的下界正是 6.13（390）/ 10.36（480），远小于 12，**失败是结构性的**，简报实测 18960 / 2201 次与此完全吻合。零容忍意味着容错为 0，不存在"降低发生率"的中间路线。

反过来说，**现行 z-order 是资产而非负担**：太阳顶层 ⇒ 太阳的 `center` 与 `target` 两条断言**永远不可能被任何其他元素夺走**，只要太阳自己的圆盖住 `P_S`。这把一条零容忍门禁从"概率问题"降级为"一个 clamp 常数是否 < 12"的**编译期可证命题**。方案 D 完整继承了这份资产，这是我保留 z-order 的根本理由。

### 前提 C（缩小太阳）——**方向正确，机制错误**

简报的关键洞察是对的：**太阳零偏移 ⇒ 任何 `R_s > 0` 都保证太阳自命中**。但它从这个洞察推出了错误的动作。真正的命题是更弱的：

> **太阳 target 成立 ⟺ `|C_S − P_S| < R_S`**（因为太阳顶层，无人能抢）。

"零偏移"只是**充分条件**，不是必要条件。C 的做法是压死 `|C_S − P_S| = 0` 然后削 `R_S`；D 的做法是保住 `R_S = 12` 然后让 `|C_S − P_S|` 在 `[0, 11.0]` 内浮动。两者都满足那个 ⟺，但代价天差地别：

| | 前提 C（缩小） | 前提 D（平移） |
|---|---|---|
| 390×844 所需值 | `R_S ≤ 6.13` ⇒ **直径 12 px** | `s ≤ 6.87` ⇒ 直径仍 24 px |
| 太阳可点面积 | 113 px²（降至 **25%**） | 452 px²（**100%**），仅在最坏构型被地/月圆切掉 0 px²（太阳顶层，被切的是地月） |
| 影响时长 | **永久**（所有帧、所有移动设备） | **瞬态**（仅 `anchor < 25.2` 的帧） |
| 受损对象 | **主 CTA「登录」** | 次级入口中离太阳最近的那一个 |
| 合规性 | 12 px 直径，AA 不达标且无豁免 | 三者均 24 px，达标 |

**登录是本页唯一的主转化路径**；把它的有效点击面积砍到四分之一、命中直径降到 12 px（≈ 指尖接触椭圆短轴的 1/4），按 Fitts 定律等价于把索引难度提高 ~1 bit，误点率在移动端将显著上升——而这个代价是为了修一个**次级入口在 0.565% 的帧里的中心探针归属问题**。代价与收益不成比例。**否决 C 的缩小机制，采纳 C 的"太阳让位"语义，改用平移执行。**

## 1.3 前提 D 的正确性证明

设 `a = anchor = |P_S − M0| ≥ 14.2`（包络守卫），`R_EM = R_S = 12`。逐条验证四类门禁断言：

**(D1) 太阳 target = 100%（零容忍）**
`|C_S − P_S| = s ≤ MAX_OFF_S = 11.0 < 12 = R_S` ⇒ `P_S` 恒在太阳圆内；太阳 z 最高 ⇒ 无人可夺。**由 clamp 常数直接保证，与几何包络无关**，是全合同中唯一不依赖任何实测数据的断言。

**(D2) 太阳 center = 100%**
探针点即 `C_S`，恒在自身圆心；顶层 z。∎

**(D3) 地/月 center**
需 `|C_X − C_S| > 12`。阶段 2 的 `s_X` 定义即在求解 `sqrt((x_X+s)² + w_X²) = R_YIELD`，故 `s ≥ s_X` 时 `|C_X − C_S| ≥ R_YIELD = 13.0 > 12`，余量 1.0 px。另一侧的遮挡源是对方按钮：`|C_E − C_M| = gap ≥ 24 > 12`，不可能。∎

**(D4) 地/月 target**
需 `P_X` 在自身圆内且无人遮挡。
- 自身：`|C_X − P_X| = t ≤ MAX_OFF = 11.4 < 12`，余量 0.6 px。
- 太阳遮挡？`|C_S − P_X| ≥ (a + s) − d/2 ≥ 18.33 − 2.95 = 15.38 > 12`（太阳只会远离，单调性见下）。
- 对方遮挡？`|C_E − P_M| = |C_M − P_E| = d + t = (SEP_X + d)/2 ≥ (24.4+1.6)/2 = 13.0 > 12`（`d ≥ d₀` 时）。∎

**(D5) geometry ≥ 24.0**
`d ≥ d₀` 时 `gap = d + 2t ≡ SEP_X = 24.4`（欧氏），余量 0.4 px。∎

**(D6) 太阳位移的单调性（阶段 2 不会制造新遮挡）**
令 `p = (C_X − M0)·u_s`，则 `|C_X − M0| = gap/2 = 12.2 ⇒ p ≤ 12.2 < 14.2 ≤ a`，故 `x_X = a − p > 0`。于是 `|C_X − C_S|² = (x_X + s)² + w_X²` 关于 `s` **严格单调增**；同理 `|P_X − C_S| ≥ (a + s) − d/2` 也单调增。**太阳沿 `+u_s` 的移动对所有四个受影响距离都是单调改善的**，不存在"修好一个弄坏另一个"的耦合。∎

**(D7) 桌面零漂移**
`1280×900`：`w_X ≤ 12.2`，`x_X ≥ 53.47 − 12.2 = 41.27 > sqrt(169 − w²) ≤ 13` ⇒ `s_X ≡ 0` ⇒ `s ≡ 0`，太阳按钮**逐位不动**；地月公式与方案 X 完全相同。**该视口的所有输出与当前方案 X 逐比特一致。**∎

## 1.4 定理 2：移动端「三个 24 px 目标互不重叠」本身不可能（这解释了为何前三次都失败）

> **定理 2.** 设三按钮半径均为 12，且各自偏移必须 < 12（否则自身 target 失败）。则"三者两两中心距 ≥ 24"要求 `anchor ≥ 36.2 − s_max > 24.2`。

*证明.* 取最坏构型 `e ∥ u_s`。`C_E, C_M` 距 `M0` 各 12.2（引理，见 1.1）；靠太阳一侧的中心距 `P_S` 为 `a − 12.2`。要求其 ≥ 24 ⇒ `a + s ≥ 36.2`，而 `s < 12` ⇒ `a > 24.2`。实测 `anchor_min` 在 390 为 18.33、在 480 为 22.56，**均不满足**。∎

推论：**在 390/480 视口，太阳热区与地月热区之一必然部分重叠，任何布局方案都无法避免。**这正是前三次实施"越修越崩"的根因——它们在追求一个不可达的目标（互不重叠），于是不断在"谁让谁"之间做离散选择，而离散选择必然产生跳变。

因此我把设计目标从**「热区互不重叠」**改判为：

> **可裁决目标（M）：三个探针点（各自的中心点与各自的天体投影点，共 6 个）必须各自被其所有者拥有；热区面积允许被更高 z 的入口部分遮挡，但遮挡后的有效面积不低于 60%。**

这与两套既有门禁断言的语义**完全一致**（它们从来只测探针归属，从不测面积互斥），而且是可满足的。`R_YIELD = 13.0` 下最坏遮挡为两圆心距 13、半径 12 的透镜：面积 156.2 px²，占 452.4 px² 的 **34.5%**，剩余 65.5%（等效直径 19.3 px）**> 60% 底线**。且该最坏值只在 `anchor = 18.33` 的瞬时构型出现；`anchor` 中位数 27.31 时净空为 `min(13, 15.11)=15.11`，遮挡降至 23%。

## 1.6 `d → 0` 奇点的处理（正面回答）

**不可能性定理的三个条件，我明确放弃 (ii)，且只在一个面积 `π·1.574² ≈ 7.8 px²` 的构型盘上放弃。**

三种放弃方式的代价对比：

| 放弃 | 后果 | 可否度量 | 裁决 |
|---|---|---|---|
| (i) 连续性 | 中心跳变 ~22.8 px；按钮在一帧内"瞬移"；**这是前三次实施的共同死因** | 门禁看不见（采样帧之间跳过去了），只有用户看得见 | **拒绝** |
| (iii) 远场恒等 | 全局位移场 ⇒ 桌面 1280 漂移 | 可度量 | **拒绝（违反不变量）** |
| **(ii) 最小间距** | 仅 `d < 1.574` 时 `gap < 24` | **可度量、可门禁、可预算**（geometry 门禁本就留了 0.5%） | **采纳** |

放弃 (ii) 的具体形式是让 `t` 随 `d` 线性归零：`|ΔC| = t(d) ≤ 7.125·d → 0`，**位移场的模趋于 0，于是方向未定义这件事不再有后果**，映射 `F` 在 `r = 0` 处连续（取 `F(0) = 恒等`）。这是唯一一种能把"方向奇点"变成"可去奇点"的构造：不选方向，而是让方向的权重归零。

**对 `d = 0` 时用户体验的交代**：此时两个按钮完全重合，月球被地球（z=20 > 10）压住，指针不可达。但这是**物理上的地月掩食**（月球投影穿过地球投影），其一，实测 600 帧 × 4 视口 `d_min = 2.140`，从未接近；其二，即便发生，月球按钮**仍在 DOM 中、仍 visible、仍可 Tab 聚焦并回车激活**——键盘通路不经过 `elementFromPoint`，**入口在任何构型下都不会消失**。这是"不得删除或降级月球入口"这条不变量的真正兑现方式：把可达性的底线放在键盘上，而不是放在一个数学上不可能恒成立的指针几何上。

## 1.7 390×844 的 9.6% 如何处理：**不接受"不被覆盖"的现状，直接修复并纳入门禁**

简报问"是否接受该视口不被 center 门禁覆盖"。**不接受**，理由有三：

1. `verify_solar_precision` 在 390×844 **确实断言了三按钮的 `centerOwned`**。当前无保护方案在该视口有 9.6% 的帧使某个地月中心落入太阳圆——也就是说这条断言**有 ~9.6% 的概率随机失败**。它现在为真是运气，不是性质。留着它就是留一颗定时炸弹（薄片测试 flaky），而且它会在未来某次无关改动的 CI 里炸，把调查成本转嫁给毫不知情的人。
2. 390×844 是 iPhone 12/13/14 的逻辑分辨率，是**真实用户占比最高的移动视口之一**，不是边角案例。
3. 方案 D 在该视口的预测是 **0 失败**（净空 13.0），修复它不需要任何额外代价。既然免费，就没有理由留着缺陷。

**因此本合同要求：把 `390×844` 加入 `verify_solar_hit_targets` 的完整 center/target/geometry 电池，并新增 `360×740` 作为最窄受支持视口。** 门禁集合取两脚本视口的并集再加 360×740，共 7 个。

## 1.8 视觉与产品影响的交代

- **默认态**：三个热区按钮必须保持完全透明，太阳位移（≤ 6.87 px @390，0 @桌面）**不产生任何可见像素变化**。
- **聚焦态**：`:focus-visible` 圆环画在按钮上，因而会带着位移。最坏 6.87 px 偏移对 24 px 环而言仍与太阳精灵重叠 ≥ 71%，且同一时刻只有一个入口聚焦、三者 `aria-label` 互异，指代不产生歧义。
- **明确禁止**：新增任何常显的"热区提示"图形——它会把位移暴露成视觉错位。这也是我不需要回答"是否同步缩小视觉提示"的原因：没有视觉提示可缩。
- **聚焦时热区漂移**：按钮中心随天体逐帧移动本就是正确行为（天体在动），不做冻结。**冻结 = 依赖历史帧状态 = 被明令禁止的第三类错误。**

## 3.6 失败判据

1. **任一 FAIL 级断言触发 ⇒ 门禁失败，PR 阻断。** 不接受"重跑一次就绿了"作为处置；薄片本身即缺陷。
2. **任一 WARN 级断言触发 ⇒ 门禁通过但报告标红，须在证据包内写明人工确认结论**（例如"`anchor_min` 降到 16.2，仍高于 14.2 硬底，原因是新增 360×740 视口，符合预期"）。
3. **H1/H2/H3/H4 出现失败帧时，报告必须对每个失败帧输出分类标签**，三选一：`BAND`（`d < 1.6`，属已声明的退化带）／`UNREADY`（未通过就绪门，应已被剔除，若出现说明就绪门有洞）／`REAL`（既非带内也非未就绪）。**出现任何一个 `REAL` 即判定设计或实现失效**，不得以"低于 0.5% 阈值"为由放行——0.5% 的预算**只留给退化带**，不留给未知原因。
4. **离线连续性扫描与时间反演测试失败 ⇒ 阻断，且不接受 DOM 门禁全绿作为抗辩**（CE-4/CE-6/CE-7 已证明 DOM 门禁对这三类死因是盲的）。
5. **证据包必须包含**：7 视口 × 每视口的 `d`/`anchor` 分位数表（min/p01/median/max）、`max s`、`max t`、最小净空、`dropped` 计数、E5 覆盖度直方图，以及 8 条反例注入的对照表。缺任一项视为证据不完整，等同失败。

# 4. 不变量（沿用 / 新增 / 修订）

## 4.1 沿用且不修订

1. 三入口键盘可达；Tab 序 **日 → 地 → 月**；三个 `aria-label` 逐字节不变。
2. 不得修改 Three.js 材质、着色器、几何体参数。**本方案只写 DOM 覆盖层的位置，不触碰渲染管线。**
3. 桌面 1280 视口既有布局**零漂移**——本方案将其从"人工承诺"升格为**可证命题 + FAIL 级断言 G4**（`s ≡ 0.0` 精确相等，且地月公式与方案 X 逐位相同）。
4. 禁止 `pointer-events: none`、禁止隐藏天体、禁止改 FOV。**另新增禁止修改相机距离/朝向**——它是唯一能真正抬高 `anchor` 的手段（移动端 18 → 桌面 53 的差距正源于此），因而也是最诱人的越界口；但它会同时改变整个移动端构图并冲击视觉反馈门禁，**超出热区修复的授权范围**。若未来确需提高移动端可达性余量，这是**唯一有效的方向**，但必须作为独立提案走视觉评审。
5. 禁止「无解时摘除按钮」。本方案通过**取消求解器本身**来兑现：布局是一次成型的闭式纯函数，不存在"无解"这一状态（H10 静态检查 + G6 全函数性断言双重锁定）。
6. **不得删除或降级月球入口。**兑现方式见 1.6：即便在数学上不可能保住指针可达性的 `d = 0` 构型，月球按钮仍 `connected`、`visible`、可 Tab 聚焦、可 Enter 激活（H6 要求 100%，**含退化带、含未就绪帧**）。

## 4.2 修订一条（附论证）

> **原：** 移动端触控尺寸 ≥ 24 px。
> **新：** 移动端触控尺寸 ≥ 24 px（**三个入口全部保持 24×24，本次不修订该数值**）；**补充下位条款**：当两个入口的热区因投影拥挤而不可避免地重叠时，被上层遮挡后的**有效可点面积不得低于满圆的 60%**（等效直径 ≥ 18.6 px），且**双方的探针点（自身中心 + 自身天体投影点）必须始终由自身拥有**。

**修订论证**：这不是对 24 px 的削弱，而是对一个此前**未被定义**的情形补充规则。定理 2 已证：在 `anchor < 24.2` 的移动视口下，三个 24 px 圆形目标**两两不重叠是数学上不可能的**（需 `anchor ≥ 24.2`，实测 390 为 18.33、480 为 22.56）。原不变量对"重叠后怎么办"完全沉默，而前三次实施正是在这个沉默地带各自发明了互不相容的规则（摘除按钮／对称分居／z 调换）。补充条款把沉默地带变成可裁决、可度量、可门禁的区域（G7 断言 ≥ 0.60，设计实得 0.655）。

同时应当记录：WCAG 2.2 SC 2.5.8 的 Spacing 豁免条款在本场景**不可满足**（它要求各目标的 24 px 圆互不相交，而 `anchor ≈ 18 < 24`），因此"保持三个目标都是 24×24 的实际尺寸"是本场景下**唯一可论证的合规姿态**——这恰恰是否决前提 A 与前提 C 的合规依据，也是把 24 px 写死在 H7 里的理由。

## 4.3 新增五条

7. **太阳按钮位移 `‖C_S − P_S‖ ≤ 11.0 px`，且在视口宽 ≥ 1280 时恒为 0.0。**（G2b + G4）前半句是太阳零容忍门禁的编译期充分条件；后半句是桌面零漂移的形式化。
8. **z-order 固定为 太阳 30 / 地球 20 / 月球 10，升格为承重不变量。**（H5）它不再只是视觉层级，而是"太阳 target 100%"的两个必要条件之一（另一个是条款 7）。任何改动 z 序的提案必须同时给出太阳 target 的新证明。
9. **热区按钮在默认态必须完全透明；禁止新增任何常显的热区提示图形。**（见 1.8）位移机制的可接受性建立在"位移不可见"之上。
10. **布局函数必须是纯函数，且不得包含视口断点。**（时间反演测试 + 视口连续性扫描）禁止滞回、平滑、缓存上一帧、媒体查询分支。判别准则写明：允许 `min/max/clamp/sqrt(max(·,0))` 这类**输出值连续**的分段构造；禁止 `sign`、在两个**不同方向向量**之间做离散选择、`argmin` 取方向。
11. **包络守卫常驻：`anchor_min ≥ 14.2`（FAIL）、`d < 1.6` 占比 ≤ 0.5%（FAIL）。**（E1/E3）本设计的正确性依赖这两条关于场景几何的前提；把前提本身变成断言，是为了在相机、缩放或星历精度发生任何无关改动时**立刻**得到通知，而不是等到某个移动端用户点不动月球。

# 5. 对简报的两点更正与一点补充

1. **§5.3 的结论需要限定条件。** 表中"旋转会减小 gap"是在 `t` 固定的前提下测的。若允许 `t` 随旋转角 `θ` 补偿（`2t = −d·cosθ + sqrt(SEP_X² − d²sin²θ)`），角自由度并非为零，而是被 `t ≤ MAX_OFF` 限制在 `θ ≤ 43.4°`（`d = 2.14` 时）。但即使用满这 43.4°，390×844 最坏构型下的净空仅 `≈ 11.9 < 12`，**仍然不够**；且引入旋转会让内积 `(C_M−C_E)·(P_M−P_E)` 具备变号的可能（第二重障碍）。**结论（"方向自由度不可用"）正确，但理由应改为"补偿后的角自由度不足以跨越 12 px 边界，且代价是打开标签互换的口子"**，而不是"无任何方向自由度"。这个更正很重要：否则下一个人会重新发现这 43.4° 并误以为找到了出路。

2. **§二 geometry 判据的推导注释需订正。** `(w_E+w_M)/2 = 24.0` 是方盒半宽之和；对方盒，不相交的判据是 **Chebyshev ≥ 24**。因为实际元素是圆（`border-radius: 50%`，且已实测 `elementFromPoint` 尊重圆裁剪），正确判据是**欧氏 ≥ 24**，数值巧合相同但语义不同。请在脚本注释中改写推导，否则后续有人按方盒语义把判据改成 Chebyshev 时，会在对角构型上放过真实重叠。

3. **补充一条可直接用于自检的恒等式**：`最坏 |C − S| = anchor_min − SEP_X/2`（见 1.1，四视口验证残差 ≤ 0.02 px）。它把"跑 20 万帧才知道最坏情况"变成"读两个数就能预测"，建议固化进探针报告，作为实测与模型的一致性校验项——任何一次两者背离，都意味着实现偏离了设计。

# 6. 一页纸交底

**问题的真实形状**：移动端三个天体投影挤在 ~20 px 邻域内，而三个入口各需 24 px。定理 2 说互不重叠不可能，不可能性定理说"处处保持间距的连续位移场"不可能。前三次实施都死在试图同时满足两个不可能，于是被迫在离散分支之间跳。

**解法**：把不可能的目标换成可能的目标（**探针归属**而非**面积互斥**），把三个不可能条件中代价最小的那个（**最小间距**，且只在 `d < 1.574` 的 7.8 px² 构型盘上）放弃，并把"谁让位"从**缩尺寸**换成**平移**——因为太阳顶层 z 使得它的两条零容忍断言只依赖 `‖C_S − P_S‖ < 12`，而这是一个 clamp 常数就能保证的编译期事实。

**代价清单**（全部可度量、已定阈值）：太阳按钮在 390×844 最多平移 6.87 px（不可见，桌面恒为 0）；地球或月球在最坏构型下被太阳遮掉 34.5% 面积（保留 65.5% > 60% 底线）；`d < 1.574` 时地月间距跌破 24（实测占比 0%，预算 0.5%，且该构型下键盘通路仍然畅通）。

**没有付出的代价**：三个入口的触控尺寸、z 序语义、桌面布局、渲染管线、FOV、相机、`aria-label`、Tab 序——全部零改动。
